# 诊断扩展计划 — XGBoost / MCTS 增强如何补完 omega 的诊断闭环 (2026-09-10)

> 触发：MCTS/XGBoost 增强讨论后的问题——**这两个增强是否也能扩展 omega 自身的"诊断"能力？**
> 关联：`docs/omega-mcts-wiring-plan-2026-09.md`（MCTS 接线三步）·
> `docs/technical-review-optuna-hpo-2026-09.md`（BO 分工）
> 落位：NAS 私有侧（origin only）；内容为设计文档，公开与否另行评审。

## 1. 先盘点：omega 已有的诊断链（代码实况）

```
CompileGate（硬判据：编译通过/不通过）                    ← omega/loop/compile_gate.py
  → ErrorClassifier 三层                                  ← omega/classifier/
      ① layer1_rules.py    规则层：PatternMatch / match_known_pattern
                            + strategy_for / fix_strategies_for（错误类别 → 修复策略）
      ② layer2_nlp.py      NLP 光谱：TokenJaccard / EditDistance / BM25 / Embedding
                            + AlgorithmVote（多算法投票）
      ③ layer3_llm_judge.py LLM judge（JudgeResult / LLMJudge）
  → error_signature（规范化 + 哈希）                       ← omega/loop/error_memory.py
  → ProofErrorMemory（error_signature → proven fix 记忆）
  → ConvergenceTracker / BudgetTracker（收敛 + 资源）
  → verifier / verify/（独立验证模块）
```

**这张链已经很接近诊断栈**：规则层≈符号白箱、NLP 光谱≈统计层、LLM judge≈神经层——
**三层分类器本身就是"诊断栈分层"的一次工程实现**（规则→统计→神经，逐层兜底）。

**但对照诊断的操作性定义（定位组件/阶段/机制 + 可证伪验证 + 可执行修复靶点），有四个缺口**：

| # | 缺口 | 现状 |
|:--:|:--|:--|
| ① | **无"定位"** | 知道**错在哪类**（分类），不知道**错在哪一步/哪个分支/哪个深度** |
| ② | **无"归因"** | 多因素同时存在时，谁贡献最大（无分解/贡献度） |
| ③ | **无"盲区检测"** | "没试过的路径"被默认当作"没价值"，而非**诊断信息**（覆盖缺口） |
| ④ | **无"修复验证"** | 改了之后**负担是否真消失 vs 搬家**（SCOPED INT2 判据缺失） |

## 2. MCTS 增强补什么（定位 / 轨迹 / 盲区）

**核心命题：MCTS 的搜索树本身就是一棵"诊断数据结构"**——它在搜索的同时免费产出定位证据。

| MCTS 产物 | 诊断价值 | 补哪个缺口 |
|:--|:--|:--:|
| **访问计数 $N(s,a)$** | **卡点定位**：高访问 + 低价值 = 反复失败的死胡同（病灶） | ① |
| **Q 值分布** | 每步"健康度"（低 Q 路径即失败热区） | ① |
| **未探索分支** | **盲区清单**——"没试过"本身就是诊断信息（覆盖缺口） | ③ |
| **backprop 路径** | **失败传播链**：哪一次决策把整条路径带进失败 | ② |
| **树形状**（深/宽/偏斜） | 问题结构诊断（"需要深分解" vs "需要宽分支"） | ① |
| **编译错误 × 树位置** | **错误热区图**：哪类 tactic 在哪个深度最常失败 | ① |

⭐ **与"分形盆"研究的直接接口**（见 `docs/` 同批记录 + 内部 wiki）：
- 搜索树里的"**高访问 + 低价值**"节点 ≈ 论文中的**鞍点**（轨迹被弱吸引却无法离开）
- **访问分布的熵** ≈ **盆熵**的廉价代理 → 可量化"**这次搜索有多'看运气'**"
- 未探索分支的比例 ≈ 覆盖缺口比率
→ 这让 omega 的诊断指标**有现成的理论对标**（不必自己造度量）

## 3. XGBoost 增强补什么（归因 / 预测 / 靶点）

| XGBoost 能力 | 诊断价值 | 补哪个缺口 |
|:--|:--|:--:|
| **特征重要性** | **失败归因**：哪个特征（错误类别 × 深度 × 前序动作 × prover 来源）贡献最大 | ② |
| 学「(状态特征) → 失败概率」 | **事前诊断**：在尝试之前预测这条路大概率失败 → 省预算（也直接喂 MCTS 的先验 $P(s,a)$） | ①③ |
| 学「error_signature → 修复成功率」 | **修复靶点排序**：现有 `fix_strategies_for` 是**静态规则表**，GBDT 是**数据驱动**（可给出优先级与置信度） | ④ |
| **残差/误分类样本分析** | **罕见失败模式发现**：模型预测错的样本 = 尚未被现有分类器覆盖的新类别 | 新类别 |
| GBDT 替代 rollout（AlphaZero 路线） | 搜索加速，**且同时输出价值与归因**（不是黑箱加速） | 效率 |

## 4. 合起来：一个完整的诊断闭环（现状 + 增强）

```
现状:  分类(是什么错) ──→ 修复(怎么修)          ← 缺"在哪错 / 为什么错 / 修好了吗"

MCTS 补:   在哪儿错(树位置) + 盲区在哪(未探索) + 失败传播链
XGBoost 补: 为什么错(归因) + 会不会错(预测) + 修哪个最好(靶点排序)
验证补:     修完之后 —— 负担真消失 vs 搬家（对照重跑 + 收敛/预算对比）
```

**与三范式的精确映射**：

| 诊断范式 | omega 现有 | 增强后 |
|:--|:--|:--|
| **机制诊断**（Probe） | CompileGate + 三层分类器 | **+ 树位置定位**（错误热区图） |
| **过程审计**（Auditor） | ErrorMemory + ConvergenceTracker | **+ 完整轨迹树**（每步选择理由/访问数/价值 = 可审计证据链） |
| **对抗评审**（Reviewer） | **三个独立 prover 已存在**（ar / re / go） | + 交叉投票 + **分歧本身即诊断信号**（哪个 prover 在什么题上系统性不同） |
| **监控巡更**（Monitor） | ConvergenceTracker | **+ 修复后负担验证**（重跑对照，回答缺口④） |

## 5. 落地三步（叠加不替换）

1. **接线 `MCTSStrategy` 时同步导出"诊断视图"**（不改现有分类器）：
   卡点节点（高 $N$ 低 $Q$）· 盲区分支 · 错误热区（错误类别 × 深度）
2. **XGBoost 学两张表**：
   - **价值表** → 搜索加速（替代部分 rollout，AlphaZero 路线）
   - **诊断表** → 归因（特征重要性）+ 预测（失败概率）+ 靶点排序（修复成功率）
   - 现有 `fix_strategies_for` **保留为 fallback**（离线模型不可用时降级，同 system-agent 的依赖分层纪律）
3. **诊断报告输出**（对一次失败的定理）：
   ```
   哪一层 / 哪一步 / 哪类错误 / 建议改什么 / 为什么（特征重要性 top-k）/ 修复后是否真解决
   ```

## 6. 战略含义

⭐ **omega 是"诊断方法学"的最佳实验场**，因为它满足诊断的三个硬条件：

| 条件 | omega 的对应 |
|:--|:--|
| **可证伪验证** | Lean 编译器 = 不可争辩的硬判据（不像内容合规的软判据） |
| **可枚举动作空间** | tactic / lemma 选择是离散可枚举的（MCTS 可行域） |
| **可累积轨迹** | ErrorMemory + 未来的 proof tree → 特征矩阵 |

→ **在 omega 上把三范式 + 分层栈验证到位，再把方法论迁移到内容合规域**（同构、不同域、判据由硬变软）。
→ 另一重价值：omega 的**诊断报告本身是可演示的能力证明**（"让证明成功率提升 X%，且能解释为什么失败"），
   比 PPT 更硬——与 `docs/plan/` 中技术人设页的"能跑的成果 > 细节清单"同源。

## 7. 风险与边界

| 风险 | 对策 |
|:--|:--|
| 诊断输出膨胀（每个失败都出长报告） | 只对"高价值定理"或"重复失败模式"出报告；其余只记结构化标签 |
| GBDT 小样本过拟合（轨迹初期很少） | 分层纪律：轨迹 <50 条只用规则层（现有三层分类器）；≥200 条再上 GBDT |
| MCTS 与诊断目标冲突（搜索要快 vs 诊断要全） | 分离：搜索用价值表（求快），诊断用独立采样（求覆盖，可牺牲效率） |
| 把"搜索失败"误读成"定理不可证" | 诊断报告须显式声明"这是**搜索策略**的失败，不是**问题**的失败"（可证伪性纪律） |
