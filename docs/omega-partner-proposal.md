## 一、项目概览

### 1.1 定位

Ω-Architect 是一个**面向物理/光学/量子系统的开放形式化定理证明框架**，核心思路是 **Loop Engineering** — 将 LLM 证明生成、Lean 编译验证、MCP 引理搜索和 GRPO 策略学习整合为统一的 agentic loop。

### 1.2 当前状态

| 层面 | 状态 | 关键指标 |
|:-----|:-----|:---------|
| L1 资源抽象 | ✅ 完成 | GPU 检测、三后端统一、四维预算追踪（$/token/时间/尝试） |
| L2 证明引擎(DFS) | ✅ 完成 | Dialogue Loop + Compile Gate + 13类错误分类 + 搜索限制 |
| L2 证明引擎(Beam/Hybrid) | ✅ 完成 | 4 策略引擎（GoProver/ReProver/ArchProver/Ensemble）+ ModeRouter |
| L3 编排器 | ✅ 完成 | 8 状态机 + 8 原语 + Blueprint DAG + 失败恢复 |
| L4 策略学习(LUFFY GRPO) | ✅ P2完成 | On-policy/Off-policy 混合 + QLoRA 4-bit + 8域分类器 |
| Plan Layer (运筹) | ✅ 完成 | PlanManager + ProofAllocator + 预算感知路由 |
| 回归测试 | ✅ | 694 tests, 全 pass |
| MiniF2F 抽样 | ❌ **40%→目标95%** | Easy 3/3 ✅, Medium 1/4, Hard 0/3 |

### 1.3 核心创新

**Loop Engineering + 策略学习的四层架构**:

```
L1: 资源抽象     → API/GPU/Memory 统一, 自动路由
L2: 证明引擎      → DFS/Beam/Hybrid 多模式, Compile 作为本地 gate
L3: 编排器        → 8 状态机 + Blueprint DAG 分解
L4: 策略学习      → LUFFY GRPO (On/Off-Policy + QLoRA)
```

## 三、从 QiMeng-PRepair (2604.05963) 到 Ω-Architect 的策略转移

### 3.1 EA-GRPO 是 P3-P4 的核心算法升级

QiMeng-PRepair 发表于 ACL 2026 主会，提出了 **EA-GRPO** (Edit-Aware Group Relative Policy Optimization)。经过全文分析，以下是可移植到 omega 的四个关键点：

#### 转移点 1: Reward 改造

```python
# naive GRPO (omega 当前)
reward = 1.0 if compile_passes else 0.0

# EA-GRPO (待集成)
group_accuracy = sum(correct_samples) / n
if group_accuracy >= alpha:           # 动态开关
    z = (edit_cost - mean) / std      # group 内标准化
    penalty = sigmoid(z)              # 惩罚系数 [0, 1]
    reward = 1.0 - beta * penalty     # beta 控制惩罚强度
else:
    reward = 1.0                      # 不惩罚(组准确率不够高时)
```

**Key insight**: 编辑惩罚只在 group accuracy ≥ α 时激活。这解决了 naive GRPO 中"大段重写碰对答案"的 over-editing 问题。

#### 转移点 2: fixp@k 评估指标

| 指标 | 含义 | omega 当前 | EA-GRPO 后 |
|:-----|:-----|:-----------|:------------|
| pass@k | 正确率 | ✅ 有 | ✅ 保持 |
| fixp@k | 正确率 × 编辑精确率 (DEC ≤ p·DEC_golden) | ❌ 缺失 | **新增** |

edit cost `DEC(X, Y')` = 行级 Levenshtein 距离 / 总行数。

#### 转移点 3: 线级 vs token 级 edit cost

论文验证了线级 DEC 的优势：
- 语义一致性更好（替换一行 = 一行成本，而非3个token中1个）
- 与 `git diff` 对齐，开发者审阅自然
- token 级/线级趋势完全一致（Table 6 验证）

#### 转移点 4: Speculative Edits 加速

低 edit cost → Prompt Lookup Decoding 接受率 ↑ → 推理吞吐↑。EA-GRPO 在 Verilog 上 TPS 从 15.87→28.15 (+77%)。
